# 独立复审机制 —— 防 AI 自主任务"过早收口 / 自评偏见"的可移植方案

> 这是一套让"AI 自主驱动的长任务"在宣布完成前，被**独立第三方视角**强制审一遍的机制。
> 解决的核心问题：**驱动任务的 AI 会通过自己的复审来合理化自己的草率结论**。
> 适用于任何 AI agent 长任务（渗透/调研/数据处理/代码审查…），与具体框架无关。
> 自包含，照搬即可。

---

## 一、它解决什么问题（先讲清病根）

让一个 AI 自主跑长任务（多步、多轮），最常见的失败**不是能力不够，而是它急于收工**：
- 把 90 个待测对象**按表面特征归类一笔带过**，没逐个看，就宣布"都一样/没东西了"；
- 把"**我够不着**（被限流/没权限/超时）"偷换成"**它是安全的**"；
- 给一个**没做对照实验**的结论打满分置信度；
- 让它**自己复审自己**——结果它写"我这是去重不是偷懒"，把所有自检变成橡皮图章。

**关键认知：自评治不了自评偏见。** 一个想收工的 agent，会让它自己的每一道自检都通过。
真正能拦住它的，只有一个**对"收工"没有任何投入的独立视角**。

> 真实验证：在一次渗透任务里，驱动 AI **连续 5 次**声称"探尽了"，每次被人逼一下都
> 又挖出漏掉的东西。后来上了本机制，**独立复审连续两轮各抓出一个驱动 AI 自己看不见的
> 硬伤**（一个矛盾的满分置信度结论、一个"只下载了 4/13 个资源就声称已枚举完"），
> 其中第二个直接导向了一个更高价值的漏洞。机制实测有效。

---

## 二、机制总览（三个部件）

```
驱动 AI 跑任务 ── 想宣布"完成/无更多可做" (收口断言)
                          │
                          ▼
         ┌──────────────────────────────────┐
         │ 部件1: 收口断言检测                │  ← 检测到"探尽/无东西/打不动"等措辞
         └──────────────────────────────────┘
                          │ 触发
                          ▼
         ┌──────────────────────────────────┐
         │ 部件2: 硬门 (gate)                 │  ← 没有独立复审记录 = 不许收口 (硬失败)
         └──────────────────────────────────┘
                          │ 要求
                          ▼
         ┌──────────────────────────────────┐
         │ 部件3: 独立复审员 (fresh context)  │  ← 全新上下文的 agent，只读产物，挑刺
         └──────────────────────────────────┘
                          │ 产出
                          ▼
         驱动 AI 必须逐条处理复审发现 → 才能真收口
```

三个部件缺一不可：
1. **收口断言检测**：知道驱动 AI 什么时候"想收工"——否则机制不知道何时介入。
2. **硬门**：把"收口前必须复审"变成**强制**，而不是靠驱动 AI 自觉。这是关键——
   软提示拦不住一个想跳过的 AI，必须是"没复审就过不了"。
3. **独立复审员**：一个**没参与任务、对收工零投入**的 agent，用全新视角审。
   这是唯一对症"自评偏见"的部件。

---

## 三、部件3 是核心：独立复审员

### 为什么必须"独立"
同一个 agent（同一段上下文）复审自己，会带着"我已经做了很多、该完成了"的投入去看，
自然合理化。**新开一个 agent、只给它任务产物（不给它聊天历史/不让它联网继续做）**，
它没有收工的动机，只有挑刺的职责——这才能挖出驱动 AI 不愿看见的东西。

### 怎么实现（任选一种）
- **子代理（推荐）**：在收口节点，主 agent **派生一个新 agent**，喂下面的 prompt + 任务产物路径。
- **人开新会话**：操作者复制下面的 prompt + 产物，开一个全新 AI 对话跑。
- **另一个模型**：用不同模型当复审员，独立性更强。

### 独立复审员 Prompt（核心资产，照抄改 `<任务>`）

```
你是独立复审员。你没有参与这次<任务>，对"收工/完成"没有任何投入——你的职责是用全新
视角挑出【过早收口】与【过度自信】。只读 <产物目录> 下的文件，不要联网、不要继续执行
任务、不要修改任何文件。你只读和分析。

逐项审，给出【可执行】的结论（不要泛泛而谈，要具体到 编号/对象名/证据）：
1. 过早收口：哪些结论/分支被【关闭得太早】？哪些"做完了/没东西了"的断言其实证据不足？
2. Lump 风险：哪些对象只按【表面特征】(类型/名字/状态码) 归类就被一笔带过，从没逐个
   看过真实内容？
3. "够不着"≠"它没问题"：哪些是因为【自己受限】(没权限/被限流/超时/工具不行) 而关闭，
   却被写成了"对象本身没问题"？这两者必须分开——前者是"待办(受阻)"，后者才是"已排除"。
4. 证据质量：哪些结论给了【高置信度】却没有对照实验/复现？哪些该降级？
5. 漏做面：基于现有产物，还有哪些【可做但没做】的事被跳过了？
6. 过度断言/过度保守：有没有把【疑似】当【确认】，或把【确认】写成【疑似】？

输出格式：
- 【必须重做/再查的项】(编号 + 为什么 + 下一步具体动作)
- 【该降级的结论】(证据 + 当前置信度 → 建议 + 理由)
- 【漏做的面】(对象 + 类型)
- 【收口判定】：当前是否真能收工？还是有 N 个未尽事项必须先处理？

诚实尖锐，宁可多挑。你的价值在于挑出驱动者自己看不见/不愿看见的东西。如果驱动者确实
做扎实了，也要明说"这轮收口成立"——你不是为挑而挑，是为了让收口判断可信。
```

### 复审产出怎么用
- 复审发现写进产物里一个固定区块（如 `review.md` 的 `## Independent Review`）。
- 驱动 AI **必须逐条处理**：要么照做（重查/重开/降级），要么在记录里写明【为什么驳回 + 证据】。
- 全部处理完，收口才成立。

## 四、部件2 硬门：怎么强制

光有 prompt 不够——必须有个**机械检查**卡住收口，否则驱动 AI 会跳过复审。
最简单的实现：一个**收口检查脚本**，在"宣布完成"前必须跑通。逻辑：

```python
# 伪代码 / 可直接改成你的检查脚本
CLOSURE_CLAIMS = ["无东西", "探尽", "都做完", "没问题了", "打不动",
                  "exhausted", "no more", "nothing left", "all clear"]

def closure_gate(产物目录):
    report = read(产物目录 + "/report.md")        # 驱动 AI 的结论文档
    if not any(c in report for c in CLOSURE_CLAIMS):
        return PASS                                # 没声称收口 → 不介入, 零日常负担

    review = read(产物目录 + "/review.md")
    if "Independent Review" not in review and "独立复审" not in review:
        return FAIL("收口硬门: 声称完成但无独立复审记录。"
                    "自评治不了自评偏见; 收口前必须派独立复审员并落记录。")  # ← 硬失败

    # 以下为【软警告】(提示, 不阻断): 帮助发现常见的过早收口
    warns = []
    if not exists(产物目录 + "/classify.txt"):     # 是否逐对象按内容看过
        warns.append("声称完成但无逐对象内容核查记录 —— 可能只按表面特征 lump")
    for 已关闭项 in 解析关闭列表(产物目录):
        if not 引用了证据(已关闭项):
            warns.append(f"{已关闭项}: 关闭但未引用证据")
        if 有屏障(已关闭项) and not 有正面排除证据(已关闭项):
            warns.append(f"{已关闭项}: 以'够不着'关闭却无'它没问题'的证据 → 应记'待办'非'已排除'")
    return PASS_WITH_WARNINGS(warns)
```

要点：
- **只在检测到收口断言时触发**——平时零负担，不烦人。
- **"缺独立复审" = 硬失败**（return FAIL），其余 = 软警告。这条硬失败是整套机制的牙齿。
- 触发词列表按你的任务领域定制。

## 五、配套：证据质量护栏（强烈建议一起上）

独立复审会抓"高置信度无对照"，但你也可以**前置**一道自动检查，防止一开始就乱打分：

```python
# 凡是标了高置信度(如 >=0.8 / "确认")的结论, 必须带 对照(Control) 或 复现(Replicated) 字段
def certainty_guard(证据文件):
    for 条目 in 解析条目(证据文件):
        if 置信度(条目) >= 0.8 and not (有"Control"字段(条目) or 有"Replicated"字段(条目)):
            warn(f"{条目}: 高置信度但无对照/复现 —— 单次观测≠确认, 补对照或降级")
```

真实案例：一个 AI 把"整站封锁了我"打了满分置信度，但**没做对照实验**（没测"换个对象还通不通"）。
这条护栏会当场拦下，逼它补对照——一补就发现根本没封，结论不成立。

## 六、采纳指南

**最小可用版（30 分钟搭起来）：**
1. 约定一个产物目录结构（report / review / evidence 几个文件）。
2. 把"独立复审员 Prompt"存成模板。
3. 立规矩：宣布完成前，**必须**新开一个 AI（或派子代理）跑这个 prompt，把发现写进 review。
4. （可选）写个 10 行收口检查脚本，检测收口措辞 + review 里有没有复审记录。

**完整版（机制化）：**
- 上面三部件全做：收口检测 + 硬门脚本 + 子代理自动派生。
- 加证据质量护栏（第五节）。
- 把"独立复审在收口前必做"写进你的 agent 系统提示/工作流，并由硬门脚本强制。

**移植注意：**
- 核心是**部件3（独立 = 新上下文）**和**部件2（硬门 = 强制）**。少了独立性，等于自评；
  少了硬门，驱动 AI 会跳过。两者缺一，机制失效。
- 部件1（收口检测）只是"何时介入"的开关，措辞按领域调。

---

## 七、为什么这套有效（一句话）

**它不是让 AI 变聪明，是让"想收工的 AI"被一个对收工零投入的独立视角强制审一遍，
并且这道审查是【硬门】不是【建议】。** AI 的草率倾向治不好，但可以被机械地拦住——
这套机制就是那道拦网。实测：连续两轮各拦下一个驱动 AI 自己看不见的过早收口。
