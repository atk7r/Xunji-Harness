# PoC 库

本工作区自有的 PoC 库，按**披露状态**分两类。与 `knowledge/`（接地知识，
只存识别签名+弱点锚点）不同，这里存**可运行的验证工具**——但同样受
`src-safety-boundary` 与 `.claude/hooks/` 硬边界约束：证明存在即停，
不做不可逆危害。

## 分类

```
poc_library/
├── normal/   普通 PoC —— 已公开披露的已知漏洞（CVE/CNVD 已分配，N-day）
│             公开 PoC/利用已存在，本库收录是为复现与变体分析。
│
└── xday/     Xday PoC —— 自主发现、未公开披露的漏洞
              厂商未修复，编号未分配或在提交流程中。敏感，外发须混淆/脱敏。
```

### 判定：放 normal 还是 xday？

| 条件 | normal | xday |
|------|:--:|:--:|
| 已有公开 CVE/CNVD 编号 | ✅ | — |
| 公开 PoC/利用已存在 | ✅ | — |
| 自主发现、尚未披露 | — | ✅ |
| 厂商已发布补丁 | ✅ | — |
| 提交流程中/待修复 | — | ✅ |

状态会变：Xday 一旦公开披露并修复，移到 normal 并更新条目状态。

## 条目结构

每个漏洞一个目录：`<分类>/<漏洞id>/`
- `README.md` — 元数据表（产品/厂商/类型/危害/状态/影响版本）+ 原理 + 用法 + 安全约束
- `poc.py` / `poc.go` / 二进制 — 验证工具
- 关联 `knowledge/<id>.md`（接地知识）与 `runs/<...>/`（复现台账）

## 外发纪律（尤其 xday）

- Xday 的源码含利用细节（如验证码求解算法）。外发交平台时用**混淆二进制**
  （`poc_*.exe` / `poc_linux64`，garble -literals，`strings` 零泄露），不外发源码。
- 漏洞描述脱敏：交平台的文字描述按需隐藏利用原理（见对应 run 目录的提交稿）。
