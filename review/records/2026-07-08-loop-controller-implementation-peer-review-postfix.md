- [claude] **The `_mentor_hints()` function silently couples to `workers.agent_discipline_issues()`**: At `implementation.diff:665` — the call is wrapped in bare `try/except` with no logging of the exception. If `workers.py` changes its API, the "done-agent-without-artifact-control" mentor hint silently disappears with no diagnostic. The reviewer didn't flag this coupling or the silent-fail pattern.
- [claude] **`_front_section_statuses` regex could match F-IDs inside Markdown code blocks**: At `implementation.diff:437` — `re.finditer(r"(?m)^###[ \t]+(F-\d+)\b", m.group(1))` does not exclude fenced code blocks. If `frontier.md` contains example F-IDs in code blocks (e.g., in a template or documentation section), they'd be incorrectly parsed as real fronts. The reviewer didn't flag this.
- [claude] **The `_field()` parser only matches single-line field values**: At `implementation.diff:568-570` — the regex `r"(?im)^\s*[-*]?\s*{re.escape(name)}\s*[:：]\s*([^\n]*)$` uses `$` to anchor, meaning multi-line field values won't be captured. Fields like `Vectors tried` or `Untried classes` that might span multiple lines in real frontier.md entries would only capture the first line. The reviewer didn't flag this.
- [claude] **No test case for "all fronts are `blocked_type_b`"**: The selftest covers `blocked_type_a`, open, closed, deferred, hyphenated, unclassified, and conflicting statuses — but never a run where ALL fronts are `blocked_type_b` (the "explored enough" category). In such a run, `open_count=0`, `deferred_count=0`, `closed_count=0`, and `blocked_type_b` fronts are excluded from `unclassified_status`. This would make `completion_pause_candidate=true` but `near_closure=false` (since there's no confirmed evidence + no closed/deferred fronts). The behavior is technically correct, but the reviewer didn't analyze this state.
- [claude] **The reviewer didn't check whether any other tool in `tools/` reads `state/loop_state.json` and gates on `coda_converged` with the old semantics**: Only user-facing docs and the loop tools were scanned. Other tools like `workers.py`, `context_pack.py`, or `saturation.py` might consume loop state and have stale assumptions about what `coda_converged=true` means. The check-run selftest passed, which provides partial coverage.
- [claude] **The CLAUDE.md change is surgical — only the Convergence Gate paragraph**: While the stale wording scan found no remaining old wording, the reviewer didn't explicitly verify that CLAUDE.md's Pause 2 section (`report.md` line range not shown in diff) doesn't also reference Coda convergence. From the current CLAUDE.md (provided in context), Pause 2 correctly triggers on "all open fronts are adjudicated AND check_run passes AND independent review is complete" — consistent with the fix. But the reviewer didn't call this out explicitly.
- [claude] **The implementation diff includes changes beyond what the report's "Main Changes" section lists**: The diff also adds `docs/WORKFLOW-reference.md` changes (Input Shape Catalog template `IS-001`, Permission/State Working Matrix template, hypotheses.md field additions, `js_inventory.py` documentation, Agent threat hypothesis workflow). The report groups these under "Claude primary-driver docs updated" which is accurate but underspecified — some of these are significant template additions, not just wording fixes. The reviewer might have missed that the `js_inventory.py` selftest registration (`diff:878`) is also included, which is a new tool registration unrelated to the loop controller.
