## Blind-spot check
- **Agent launch-to-return temporal interleaving**: The `_project_agent_lifecycle` SubagentStop handler (runtime-receipts.diff:213-239) correctly matches attempts by `agent_id` and sets state to `"returned"`. But if a SubagentStop event arrives BEFORE the corresponding PostToolUse projection (theoretically possible with hook delivery reordering at OS level), the handler finds no matching attempt, hits `continue`, and the row status remains un-updated. The PostToolUse later sets it correctly because `agent_attempts()` dynamically reads lifecycle events. This is correct but fragile — the correct outcome depends on the dual-source-of-truth between projected assignments.json and dynamic `agent_attempts()`. Any future code that reads assignments.json attempts state directly (instead of going through `agent_attempts()`) would see stale data for exactly this window.
- **`_event_destinations` static analysis gap for Bash here-strings and process substitution**: The shlex-based tokenizer handles standard command lines but `python3 <<'EOF'\nimport requests\nrequests.get('http://target')\nEOF` would have the entire heredoc body as a single shlex token. The RAW_NETWORK_CLIENT_RE regex scans the full command text and would catch `requests.get`, but the `_event_destinations` function would miss the target URL because the heredoc delimiter format isn't parsed for URLs. This is a known limitation of static analysis, noted for awareness.
- **`_assignment_assets` parser drops everything after whitespace**: The regex `XUNJI_ASSETS\s*=\s*([^\s]+)` captures only until the first whitespace. If an Agent prompt has `XUNJI_ASSETS=host1,host2 XUNJI_FRONT=F-001` (assets token followed by next token), only `host1,host2` is correctly captured. But `XUNJI_ASSETS=host1, host2` (space after comma) would only capture `host1,` — and then the split-by-comma+strip would recover `["host1", "host2"]` correctly only because `host2` appears in the same non-whitespace capture. The comma-space case actually works, but `XUNJI_ASSETS=host1` followed by a newline and the next token on a new line would NOT include `host2` from the next line. This is by design but fragile against prompt formatting variations.
- **`_launch_from_record` fallback to `response_excerpt` parsing**: At runtime-receipts.diff:319-325, when `launched_agent_id`/`agent_is_async`/`agent_status` fields are absent from the normalized event, the function falls back to parsing `response_excerpt` via `_agent_launch_fields`. `_agent_launch_fields` does `json.loads(value)` on the response string, then checks `response.get("agentId")` and `response.get("isAsync")`. If the response is a non-JSON string (e.g., error message), `json.loads` throws, returning `{}`, and the fallback produces `("", False, "")`. This means a broken Agent invocation with a garbled response would be classified as a synchronous (non-async) return with empty agent ID, silently dropping the attempt. The downstream `attempt_id` falls back to `tool_use_id`, keeping partial traceability.
- **Epoch preservation on bare continue**: The `write_contract` function (turn-contract.diff:163-179) compares `coordination_signature` and preserves the previous `fanout_epoch_started_at` when unchanged. This correctly implements the "persistent epoch across bare continues" claim. However, the signature includes `coverage_matrix.derive()` output which has a `warnings` list field — if coverage warnings change between turns (e.g., because evidence was added), the signature changes and triggers an epoch reset even though the front topology hasn't changed. This is a design tradeoff: treating new evidence as topology change. It's aggressive but fail-safe (new evidence → assume coordination needs re-evaluation).
- **`_canonical_evidence_text` concatenates all three files**: In `agent_disposition` (runtime-agent-activity.py.txt:146-150), evidence.md, frontier.md, and decisions.md are concatenated for anchor searching. An anchor like `F-002` appearing in decisions.md alone would pass the existence check even if missing from frontier.md. The actual anchor verification (`anchors_exist`) in line 165 uses `all(anchor.upper() in canonical.upper() for anchor in anchors)` — a false positive F-id match in decisions.md can satisfy a frontier.md anchor requirement. This is a minor looseness in the closed-world assumption where all three files are canonical.
- **Globally, the implementation is solid**: The three-gate merge validation (returned agent + per-asset receipts + canonical host mention), the default-fail-closed proxy, the evidence-only coverage cells (front-level vectors don't populate tested), and the coordination epoch mechanism all hold together. The prior review rounds already caught and fixed several hard issues (unguarded run_model.summary, direct egress approval wording, legacy empty-asset enforcement, unknown-destination checking). The code at this hash shows mature hardening with layered defenses.
