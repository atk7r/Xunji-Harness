## Blind-spot check
- [claude] **Epoch signature fragility chain:** The `_coordination_signature` function depends on `run_model.summary()` (line 76 of turn-contract.diff) without a try/except. If `run_model.summary()` raises (corrupt run state, missing files), `write_contract()` fails entirely, breaking turn state tracking. The coverage_matrix fallback has try/except but the top-level `run_model.summary` call does not. If the Xunji run_model module changes its summary output format, the signature will change silently, causing unexpected epoch resets across all existing runs.
- [claude] **Schema migration is read-triggered and in-memory only:** `load_assignments()` (workers.diff line 201-207) migrates schema v1→v2 in memory, but the migration only persists to disk when a write operation follows (`create_agent_assignment`, `update_agent_lifecycle`). A read-only operation (e.g., statusline reads assignments) would see the migrated structure in memory but the file remains v1 on disk. This is not a bug but creates an inconsistency window — a subsequent read from a different process would see the unmigrated v1 structure.
- [claude] **E-entry merge validation checks host presence but not temporal/causal attribution:** `_validate_asset_merge` (workers.diff lines 305-332) verifies that evidence.md E-entries mention each assigned asset hostname, but does not verify the E-entry was created BY this specific agent or AFTER its launch. A pre-existing E-entry from a prior agent or manual write would satisfy the check. This is mitigated by the concurrent action-receipt validation (which does verify agent-specific tool calls), but the E-entry gate specifically is temporally unanchored.
- [claude] **Review architecture incomplete:** The review.md notes that `glm-5.2` "failed strict parsing" in both rounds and "remains a recorded backend limitation." The required panel (Codex + kimi-k2.7-code + glm-5.2) has only 2/3 reviewers producing valid output. The CLAUDE.md review architecture states the arkcli panel should use `kimi-k2.7-code + glm-5.2`; with GLM consistently failing, the review panel is effectively degraded by one model. This is recorded but not resolved.
- [claude] **`_event_destinations` and coverage hostnames both use `_normalized_assets` which strips the scheme but may not handle all edge cases:** IP addresses with CIDR notation, IPv6 addresses in brackets, and hostnames with trailing dots (FQDN convention) are not explicitly tested in the destination extraction path. The `ipaddress` module handles IPv4/IPv6 but the `urlsplit("//" + asset)` pattern for coverage hostnames (turn_contract.diff line 224) could misparse unusual formats.
