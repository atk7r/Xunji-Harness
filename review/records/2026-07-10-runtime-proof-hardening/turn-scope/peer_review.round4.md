- [WARN] PR-008 **6-hour STALE_SECONDS creates a narrow mode-drift window** | Evidence: `turn_contract.lines-37-37` (STALE_SECONDS = 6 * 60 * 60), `turn_contract.lines-151-165` (load_contract), `turn_contract.lines-101-113` (classify_prompt) | Why: [panel:claude] A turn_contract.json remains valid for 6 hours. `classify_prompt` re-classifies each new prompt independently, which is correct. - [claude] **`output_gate.py` exception handler has a timing gap**: In `output_gate.diff:128-139`, the except block re-runs `find_active_run(RUNS)` without a session_id filter. If the initial `find_active_run` returned None (so `run_dir` was None when `turn_mode` was captured as "EXECUTE"), but the except-block retry finds a DIFFERENT run, the gate would block with the wrong run context. The `turn_mode` variable was set in the try block (line 75-82) using the ORIGINAL `run_dir`, which might differ from the except block's retry result. This edge case exists because `run_dir` is captured at line 72 but `turn_mode` depends on the contract loaded from that `run_dir` — if the except block retry finds a different run, the old `turn_mode` is stale.
- [claude] **`run_model.py` selftest exercises only 8 frontier.md formats**: The `_selftest()` in `run_model.diff:199-233` tests compound status lines, canonical fields, deferred fronts, duplicate IDs, and missing status fields. But it doesn't test edge cases like: a front with `Status: open` in a `## Closed Fronts` section, UTF-8 BOM in frontier.md, extremely long barrier class names, or concurrent modification during parsing. The `run_model.summary()` output (especially `fanout_required`) feeds directly into both the Agent Board gate and the PreToolUse blocking behavior. A parsing edge case could silently disable enforcement.
- [claude] **`classify_prompt` EXECUTE_RE greediness creates an "EXECUTE is default" effective behavior**: The design intent (per CLAUDE.md) is "ambiguous prompts default to read-only." But `EXECUTE_RE` matches 修复, 实现, 落实, 执行, 修改, 继续, 恢复, 开始, implement, fix, execute, apply, resume, continue, /loop, 彻底解决 — a very broad net. The combined effect is: PAUSE_RE is checked first (correct), EXPLAIN_RE second (correct), then EXECUTE_RE. A prompt must contain NONE of the EXECUTE_RE patterns to reach the default EXPLAIN. The selftest confirms "unrecognized English execution wording defaults read-only" (`indirect_english == EXPLAIN`), but this is because "Please deploy the prepared workflow" contains none of the EXECUTE_RE patterns. In practical red-team operation, almost every operator prompt contains at least one of 修/改/执/行/继/续/实/落/复 — so EXPLAIN as a default is rarely reached in practice. This was noted by the round 2 Claude reviewer but not addressed.
